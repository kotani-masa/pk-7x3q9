## 7.0.2（2026-10-28）

7.0.1を土台に、対抗AI（メガレックウザ）の手順を追加で修正し、ゾロアークAIを次の世代へ進めた。あわせてファイルを整理した。

### レックウザ（ai/decks/ai_rayquaza.js）

手動プレイの記録と、自動対戦で負けた試合の判断を1手ずつ確認して直した。

| 問題 | 修正 |
|---|---|
| 攻撃できる控えがいない番に、メガガルーラexの「おつかいダッシュ」（バトル場でのみ2枚ドロー）を使えていない | にげるが無料（ラティアスex）なら、メガガルーラexへにげてドローする。きぜつ後の昇格もラティアスがいればメガガルーラを優先（`kgPivot`・`kgLead`） |
| ホウオウ等の重いポケモンが前にいるのに、シアノでラティアスを取らない。控えが育ってから困る | 前がにげるエネルギー2以上で攻撃役ではない時点で、ラティアスの価値を上げる（`ltAhead`） |
| 前が動けず、ラティアスにも届かない（手札にラティアス・ハイパーボール・シアノがない）のに、ジャッジマンを抱えたまま番を終える | その状況ではジャッジマンで手札を入れ替える（`judgeStuck`） |

試して効果がなかったため入れなかったもの：2匹目以降のニャースexを出さない、役割が揃っている時のシアノを控える（いずれも2,000試合で差なし〜わずかに悪化）。

### ゾロアーク（ai/decks/ai_zoroark.js）— 次の世代

ユーザーの対戦記録で見つかった2点を直した。一律に「捨てない」「先に出す」とするのではなく、その場のサイドプランと手順で判断する。

- **とりひきのコストでくさりもちを捨てる**：くさりもちの+40が、サイドを取り切るまでに倒す相手のきぜつ線になる場合だけ残す（`mochiNeed`）。相手は場のポケモンに加え、デッキタイプから分かる主力（レックウザ相手：ファイアローex・メガレックウザex 280、メガガルーラex 300。ドラパルト相手：ドラパルトex 320）。打点はランページ250＋場のマシマシラ30＋手札のからておう40で計算し、そこから+40で届く相手がいれば、そのサイド枚数に応じて残す。どくにできない（モモワロウが残っていない）、すでにくさりもち付きのゾロアークが揃っている、+40が不要、のいずれかなら他に捨てたいカードがない時に捨ててよい。
- **ポケパッドで持ってきたゾロアを、ベンチに出す前にリーリエで山札へ戻す**：リーリエの決心は手札を山札に戻すため、その番にもともと出す・付けるつもりだったポケモン・エネルギー・どうぐは先に使ってからリーリエを使う。

記録した試合（match-mvqydt1t-2）の入力を渡し直すと、両方の場面で判断が変わることを確認した。テストも追加した（くさりもちを残す場面と、捨ててよい場面の両方）。

### ベンチマークの扱い

| ログ | ログ内のCPU表示 | 参考にした選択・問題 |

### 採用した修正

- **動けない前を解消する。** 準備済みの控えがいて前が重い場合は、ラティアスをサーチ・展開する。手張りでにげる分を揃える経路も考える。
- **ハイパーボールのコスト条件。** 本体を含む手札3枚なら2枚捨てられる。以前の「ほかに3枚以上」条件を修正。動けない局面のラティアス確保を優先する。
- **不要なカード使用を控える。** 2匹目のテラパゴスを無目的に置かず、大空洞もベンチ拡張が必要なときに使う。場の完成やHyperのコストを優先する。
- **メガを早く差し出さない。** ファイアローで攻撃・サーチできるとき、相手を倒せず返しにきぜつする本体へ単純な打点増だけで交代しない。HPを増やして耐えられる場合や、その攻撃できぜつを取れる場合は別に評価する。
- **ファイアローのサーチを攻撃価値に含める。** 150同士でも、サーチで次を作れる方へ無料でにげる価値を評価する。
- **ホウオウの手順。** 本体への手張りで炎を先に使い切る前に、2枚加速できる供給役を展開。必要な手張り分を残す条件も設ける。
- **アカマツの異なる2色。** 上位9枚を切り出してから重複を除くと1色しか残らないことがあるため、全候補から異なる色を選ぶ。
- **つけかえと無料にげるを連携。** 前が攻撃可能でも、つけかえで本体が完成し、無料で前に出せるなら候補にする。
- **早いボスでサポート権を失わない。** ホウオウ・アカマツ・手張りで本体の大きなきぜつが成立する見込みがある場合、先にその準備を進める。

### 再現で確認したこと

アップロードされた盤面を復元した分岐で、以下を実エンジン上で確認した。

1. テラパゴスで止まっていた局面から、手札3枚のHyper→ラティアス→無料にげる→かぎづめハントでサイドを取る。
2. 本体が雷・炎の2枚だった手張り直前から、3枚目を本体へ付け、ストーム150でゾロアを倒す。
3. 手動レックウザの加速直前から、ホウオウ→アカマツ→つけかえ→無料にげる→ストーム300でゾロアークを倒す。小さい獲物にボスを使ってサポート権を失わない。

試合の全ての将来の選択や勝敗を再現した意味ではない。継続検査には個人のログを同梱せず、同じ失敗条件を作った `sim/tests/test_rayquaza_engine.js` を使う。

## 7.0.0：対抗AIの構築と共進化（旧v7）

> 当時の文書をそのまま残している。ここに出てくる `sim/baselines/7.0.0/`、`sim/cli/eval_rayquaza_patch.js`、`sim/results/` の個別ファイル、`docs/` の旧ファイル名は7.0.2の整理で削除した。GitHub の commit `69c56c1` で参照できる。

### 1. この版の目的と範囲

目的は、固定した **v6ゾロアークAI** に対して、同じ60枚のレックウザ・ドラパルトを以前より勝たせること。相手AIを弱くする変更、デッキ改変、非公開情報の利用は行わない。今回更新したのは共通Controller、両デッキの方策、両デッキの数値パラメータである。

GitHubの取得元は `kotani-masa/pk-7x3q9`、参照コミットは `sim/baselines/v6/manifest.json` の `upstream`。着手時、GitHubのゲーム・AIコードと手元v6は一致していた。対戦エンジン `index.html` はこの版では変更していない。

v6の全AIソースを `sim/baselines/v6/ai/` に保存した。`ai/decks/ai_zoroark.js` がそのコピーとバイト単位で一致することをベンチマーク・テストで検査する。ゾロアークは専用Policyで動作し、今回修正した共通Controllerの判断処理を使わない。

### 2. 基本思想

1. **数値調整の前に、行動を消している実装の欠落を直す。** スコアの微調整では、未定義値によって消えた行動候補や、呼ばれない対象選択処理を救えない。
2. **一枚の価値より、攻撃までの手順を揃える。** 必要色を特定のアタッカーに集める、加速先を選ぶ、サーチで異なる役割を揃える、展開中のロックを維持する。
3. **相手の公開盤面を読めることを先に保証する。** ナイトジョーカーの名前だけを見て打点0と判断すれば、手張り・昇格・被きぜつの評価が崩れる。
4. **同じ相手・同じエンジン・同じ構築で比較する。** 相手と自分を同時更新した勝率から、自分の改善を結論しない。
5. **選別に使った乱数と最終評価の乱数を分ける。** 60試合の当たり候補をそのまま最強と呼ばない。

### 3. 最終採用した変更

| 箇所 | 問題と変更 |
|---|---|
| レックウザのdefaults | コメントに設定値が巻き込まれて未定義になっていた。値を分離し有限性をテスト |
| 共通Controllerのattach | 加速先メソッドがなく候補先頭へ付いていた。合法な対象を手張りと同じ基準で比較。つけかえの行き先も引き継ぐ |
| 行動候補の生成順 | 特性を評価する前に手張り候補を算出し、ホウオウの判断で利用できるようにした |
| シアノ | 1枚取るたびに仮の手札へ追加して再採点し、本体・ファイアロー・供給役を揃える。観測JSONは変えない |
| レックウザの手張り | 育った本体へ雷・炎・無を集中し、次にファイアロー等の攻撃を完成 |
| レックウザの脅威推定 | ナイトジョーカーのコピー先を公開盤面から計算。どく＋くさりもち、タワーも反映 |
| ドラパルト | デッキ固有の方策ファイルはv6と同じものに戻した。候補比較で加速先選択と数値を調整する方式を採用。`smartAttach=1`、`readCopiedThreat=0` が選別結果 |

ドラパルトでは、ロック維持、ハンマーの対コピー評価、モモワロウへの散布優先、アドレナブレインのコンボ、2匹目のマシマシラなども試した。しかし、それらをまとめた版は900000番台で旧327勝/1000に対して292勝/1000へ後退したため不採用とした。

その後、旧処理を維持できる2つの独立スイッチを設けて切り分けた。`smartAttach=0` は従来どおり合法候補の先頭へ加速する。`readCopiedThreat=0` は従来の脅威推定を使う。両方0・旧パラメータでは30試合の勝敗と通常ログが旧版と完全一致した。選別で残ったのは加速先選択を有効にし、コピー脅威推定を従来のままにする候補だった。アドレナブレインの移動先だけを追加する切り分けも確認用300試合で98勝、採用候補は同条件99勝だったため、今回は追加しなかった。

これは「相手の打点を知らない方が本質的に強い」という結論ではない。新しい脅威推定と、既存の昇格・手張り・危険度スコアとの整合が必要であり、妥当そうな知識を追加するだけで勝率向上を保証できないという観測である。

### 4. 実行時の構造

- エンジンは `index.html`。ヘッドレス実行は `sim/lib/headless.js`。
- AIは別のVMコンテキストにあり、エンジンの `P`、`G`、実際の山札順、相手手札にアクセスしない。
- `cpuView` の複製JSONを受け取り、カード定義 `cd` と自分のデッキリストをキャッシュする。
- 通常の意思決定は、進化・展開・特性・サーチ・加速・手張り・にげるの候補へ点数を付ける方式。準備を終えたら使えるワザから選ぶ。
- カードを複数選ぶ処理と、加速先を決める処理も方策の一部である。`decide` だけ直して完成と考えない。
- 今回のベンチマークは `search:false`。以前からある価値モデルを再学習していない。ニューラルネットの自己対戦強化学習を実施した、という意味ではない。
- 今回の自動調整は **有限候補の集団探索＋別乱数による選別**。選ばれたパラメータは `ai/params/params_dragapult.js` と `params_rayquaza.js` に入る。

### 6. 相互強化を続ける手順

今回の固定相手に対する強化は、リーグの最初の1世代と位置づける。

1. 採用AIのソース・パラメータ・エンジン・構築・成績を保存し、変更しない。
2. 次は今回のレックウザ・ドラパルトを固定して、ゾロアーク候補を調整する。
3. 最新相手に加え、v6など過去の強い相手とも対戦する。相手の混合比率を記録する。
4. 未使用の評価seedで、相手別成績と全対戦表を確認する。最新相手にだけ勝てる候補や、古い相手へ大きく退化した候補の採用を慎重にする。
5. 採用したら次世代の固定相手にする。前世代の基準を後から書き換えない。

この方式で反復改善は狙える。ただし、相性による循環、特定構築への過適応、方策表現の限界があるため、無限に単調に強くなる保証はない。古いチャンピオンを含む複数相手のリーグが必要になる。
