# 対戦の再現・AI改善用ログ

## 遊んだ試合の記録を保存する

1. 通常どおりCPU戦を行います。裏で自動記録するための設定は不要です。
2. いつものバトルログを開き、**「解析用ログを保存」**を押します。
3. `match-....pokeca.json` がダウンロードされます。このファイルを添付すれば、その時点の手札・山札順・盤面・AI判断を確認できます。

記録はメモリに**直近1試合分だけ**保持します。次の試合の準備を始めると消去し、新しい記録を作ります。試合終了直後には残るので、次の試合を始める前に保存してください。ページを閉じると未保存の記録は消えます。自動でサーバーへ送信したり、保存ファイルを増やしたりしません。
CPU戦とオフラインの1人回しが対象です。オンライン対戦は記録対象にしていません。

## 記録内容

- 両者のデッキ構成、手札、山札の並び、サイドの並び、トラッシュ、場、エネルギー、どうぐ
- ターン・使用済み特性・使用制限・状態異常などのゲーム状態
- 途中の状態変化と、それを検査するチェックサム
- エミュレータの乱数結果、コイン・シャッフルを含む選択結果
- プレイヤーのカード選択・対象選択・メニュー選択
- AIに実際に渡した情報、AIの選択結果、ゾロアークAIの判断理由
- 同梱した本体・AIのソース指紋。解析する側の版が変わっているかを確認するための情報

この情報は通常のバトルログには表示しません。AIに渡す `cpuView` の内容も増やしていません。自動対戦では記録器をエンジン側に置き、AIを別の実行環境に隔離しています。
保存したJSONには両者の非公開カードが入ります。対戦中に中身を開けば相手の手札も分かるため、解析には試合後の利用を想定しています。

## 復元とAI比較

プロジェクトのルートで実行します。

```bash
node sim/run.js replay match-xxx.pokeca.json
node sim/run.js replay match-xxx.pokeca.json --step 100 --out state.json
node sim/run.js replay match-xxx.pokeca.json --compare-ai
```

最初のコマンドは状態変化を順に適用して検査し、勝敗などを表示します。`--step` はログのイベント番号です。その時点までの盤面・両者の手札などを `--out` で書き出せます。
`--compare-ai` は、記録した公開情報と選択肢を現在のAIに順に渡し直し、元の判断と異なる箇所を表示します。ファイルの違いは `sourceChanges` に表示します。
**状態の復元**は保存された差分を適用する方式です。**AI比較**は元の試合で与えられた入力に対する判断の比較であり、別の行動を選んだ後の対戦全体を自動でやり直す機能ではありません。

## 自動対戦から記録を作る

```bash
node sim/run.js record zoroark dragapult 42 --out match42.pokeca.json
node sim/run.js replay match42.pokeca.json --compare-ai
```

通常の大量評価ではログ記録を無効にして速度を保ちます。問題のあるseedだけ `record` で取得できます。
テスト試合の記録サイズは約0.8MBでした。試合の長さや選択の回数によって変わります。

ソースを編集して配布し直す場合は、`node sim/tools/update_build.js` でソース指紋を更新してください。

## 検証済みのこと

- 記録あり・なしで同じseedの勝敗・ターン・サイド・通常ログが一致
- 保存した差分から復元した最終状態が、実際のエンジン状態と一致
- 同じAIに記録済みの入力を渡し直した選択結果が一致
- 次の対戦開始時に前の試合の記録が消える
- 差分が壊れている場合はチェックサムで検出
- AI側の実行環境に記録器が存在しない

ブラウザ上でのダウンロード操作の通し検証は未実施です。
