# 開発・検証の手引き

CPU戦で遊ぶだけなら、この文書は不要です。AIを直す・比べる・調整するときに使います。
コマンドはすべてプロジェクトのルートで `node sim/run.js <コマンド>` として実行します（一覧は `node sim/run.js help`）。追加のnpmパッケージは不要です。

## 1. よく使うコマンド

```bash
node sim/run.js test            # 判断・ルール・記録・構成のテスト（変更したら必ず）
node sim/run.js verify-info     # AIへ渡す情報に、相手の手札や山札順が漏れていないか
node sim/run.js verify-hidden   # 先読みが相手の隠れた情報に依存していないか
node sim/run.js eval 1000 40000 # ゾロアークAIの対戦評価（相手ごとの試合数、開始seed）
node sim/run.js showlog zoroark rayquaza 1234   # 1試合の通常ログ
node sim/run.js rivals eval --games 2000 --seed 1000000   # 対抗AIを凍結v6ゾロアーク相手に旧版（sim/baselines/v6）と比較
```

## 2. 相互強化（共進化）の進め方

ゾロアークAIと対抗AI（ドラパルト・メガレックウザ）を交互に強くする。各世代で「相手を固定して、自分だけを変える」。

1. **相手を固定する。** 対抗AIを強くする時は、相手ゾロアークを凍結した版にする（現在は `sim/baselines/v6/`。`rivals` は常にこれを読み込む）。ゾロアークを強くする時は、その時点の対抗AIを相手にする。
2. **負けた試合を1手ずつ見る。** `node sim/run.js record <デッキ> <デッキ> <seed> --out x.pokeca.json` で記録し、各番の手札・盤面・AIの選択を確認する。手動対戦の記録（バトルログの「解析用ログを保存」）は、人の勝ち筋を確認するのに最も役立つ。
3. **「必ず〜する」ではなく、その場の目的で判断させる。** 例：くさりもちは「サイドプランで+40が必要な相手がいるか」で残すかを決める。一律のルールは別の場面で弱くなる。
4. **同じseedで旧新を比べる。** 1,000〜2,000試合以上。差が誤差の範囲なら採用しない。調整に使ったseedは最終評価に使わない。
5. **採用した版を記録する。** `VERSION`、`docs/CHANGELOG.md`、`sim/results/summary.json`、`docs/ai_handoff.json` を更新し、`node sim/tools/update_build.js` でソース指紋を更新する。

数値パラメータの自動調整は `node sim/run.js rivals train`（対抗AI、`ai/params/` を上書き）と `node sim/run.js optimize --only zoroark`（ゾロアーク）。判断の抜けを直す前に数値だけ調整しても伸びにくい。

## 3. バージョン

配布物・README・解析ログは `VERSION` の `MAJOR.MINOR.PATCH` を使用する。現在の版は `VERSION` ファイルを参照（この文書の更新時点で **7.0.3**）。

- **PATCH**（7.0.0 → 7.0.1）：不具合修正、既存AIの判断条件・手順・評価の調整。対戦回数を増やすだけでは変更しない。
- **MINOR**（7.0.x → 7.1.0）：新デッキへの対応、新しい探索・学習機能など、既存用途を維持する機能追加。
- **MAJOR**（7.x → 8.0.0）：ログ形式・連携APIなどの互換性を壊す変更、既存用途を置き換える大きな構成変更。

過去の「v6」は6.0.0、「v7」は7.0.0として扱う。履歴のファイル名や比較データは書き換えず、以後の配布から3桁表記を使う。今回は7.0.0を基準にしたレックウザの修正なので7.0.1とした。修正の大きさを試合数や作業回数で決めない。

`node sim/tools/update_build.js` はVERSIONを検査し、`debug/build_info.js` の `version` に埋め込む。解析ログには `meta.build.version` が入る。従来の `id` はソースの指紋であり、リリース番号の代用ではない。

公開前は、VERSION・README・変更記録・配布ZIP名を一致させてから、ソース指紋を更新しテストする。

## 4. 対戦の記録と再現

### 遊んだ試合の記録を保存する

1. 通常どおりCPU戦を行います。裏で自動記録するための設定は不要です。
2. いつものバトルログを開き、**「解析用ログを保存」**を押します。
3. `match-....pokeca.json` がダウンロードされます。このファイルを添付すれば、その時点の手札・山札順・盤面・AI判断を確認できます。

記録はメモリに**直近1試合分だけ**保持します。次の試合の準備を始めると消去し、新しい記録を作ります。試合終了直後には残るので、次の試合を始める前に保存してください。ページを閉じると未保存の記録は消えます。自動でサーバーへ送信したり、保存ファイルを増やしたりしません。
CPU戦とオフラインの1人回しが対象です。オンライン対戦は記録対象にしていません。

### 記録内容

- 両者のデッキ構成、手札、山札の並び、サイドの並び、トラッシュ、場、エネルギー、どうぐ
- ターン・使用済み特性・使用制限・状態異常などのゲーム状態
- 途中の状態変化と、それを検査するチェックサム
- エミュレータの乱数結果、コイン・シャッフルを含む選択結果
- プレイヤーのカード選択・対象選択・メニュー選択
- AIに実際に渡した情報、AIの選択結果、ゾロアークAIの判断理由
- 同梱した本体・AIのソース指紋。解析する側の版が変わっているかを確認するための情報

この情報は通常のバトルログには表示しません。AIに渡す `cpuView` の内容も増やしていません。自動対戦では記録器をエンジン側に置き、AIを別の実行環境に隔離しています。
保存したJSONには両者の非公開カードが入ります。対戦中に中身を開けば相手の手札も分かるため、解析には試合後の利用を想定しています。

### 復元とAI比較

プロジェクトのルートで実行します。

```bash
node sim/run.js replay match-xxx.pokeca.json
node sim/run.js replay match-xxx.pokeca.json --step 100 --out state.json
node sim/run.js replay match-xxx.pokeca.json --compare-ai
```

最初のコマンドは状態変化を順に適用して検査し、勝敗などを表示します。`--step` はログのイベント番号です。その時点までの盤面・両者の手札などを `--out` で書き出せます。
`--compare-ai` は、記録した公開情報と選択肢を現在のAIに順に渡し直し、元の判断と異なる箇所を表示します。ファイルの違いは `sourceChanges` に表示します。
**状態の復元**は保存された差分を適用する方式です。**AI比較**は元の試合で与えられた入力に対する判断の比較であり、別の行動を選んだ後の対戦全体を自動でやり直す機能ではありません。

### 自動対戦から記録を作る

```bash
node sim/run.js record zoroark dragapult 42 --out match42.pokeca.json
node sim/run.js replay match42.pokeca.json --compare-ai
```

通常の大量評価ではログ記録を無効にして速度を保ちます。問題のあるseedだけ `record` で取得できます。
テスト試合の記録サイズは約0.8MBでした。試合の長さや選択の回数によって変わります。

ソースを編集して配布し直す場合は、`node sim/tools/update_build.js` でソース指紋を更新してください。

### 検証済みのこと

- 記録あり・なしで同じseedの勝敗・ターン・サイド・通常ログが一致
- 保存した差分から復元した最終状態が、実際のエンジン状態と一致
- 同じAIに記録済みの入力を渡し直した選択結果が一致
- 次の対戦開始時に前の試合の記録が消える
- 差分が壊れている場合はチェックサムで検出
- AI側の実行環境に記録器が存在しない

## 5. Windowsでの準備

1. https://nodejs.org から「LTS」版をインストールし、PowerShellを開き直す（または `winget install OpenJS.NodeJS.LTS`）。`node -v` で `v22.x.x` などと表示されれば成功。
2. フォルダは、空白や日本語を含まない場所に置くと入力が楽です（例：`C:\pokeca\`）。
3. PowerShellでフォルダへ移動し、`node sim\run.js test` を実行します。PCの速さは `node sim\run.js bench` で測れます。
4. 長時間の自己対戦データ収集は `node sim\run.js parallel ...`、学習は `node sim\run.js train-all ...`（ドラパルト・メガレックウザの価値関数用。`ai\models\value_model.js` が更新されるので先にコピーを保存）。現在の価値関数はデータを増やしても精度が伸びない段階で、通常は不要です。
