# Nのゾロアークex CPU AI v2

2026-10-27。エミュレータ本体は今回添付の最新版 `index (2)(1).html` を基準にしています。AI接続用の差分と、整理後のAIファイルへの読み込み先を追加しました。画面・モーションなどの処理は今回の添付版を保持しています。AI・自動対戦ツールはGitHub main `52e8bc1d346cba02d0187c8b8d270ebdaed4f941` からの追加・修正です。

## 使い方

ZIPを展開し、フォルダ内の `index.html` を開いてください。既存のCPU戦メニューから、CPU側に「Nのゾロアークex」デッキを選ぶと専用AIが自動選択されます。
`ai` フォルダを `index.html` と同じ場所に残してください。カード画像の取得にはインターネット接続が必要です。
既存フォルダへ上書きする場合はバックアップしてから行ってください。このZIPの本体は今回添付された最新版に差し替え済みです。

## 調べて分かったこと

- 自動対戦の基盤は既存の `sim/lib/headless.js` にあります。ブラウザ画面を操作せず、本体と同じルール処理をNode.jsで実行します。
- `sim/training/optimize.js` は勝率を使って行動の重みを調整するクロスエントロピー法です。ゼロから新しい戦略を発見する強化学習とは異なります。
- 既存の専用AIと学習済み価値関数はドラパルトとメガレックウザ用です。これらの価値関数をそのままゾロアークに使うことはできません。
- 既存の共通ダメージ推定では、ナイトジョーカーの借りるワザ、毒＋くさりもち、パワーレイジの判断が不足していました。今回の専用AIはここを自分で評価します。
- 現在のHTMLに対し、既存のヘッドレス起動は最後のインラインscriptを本体と誤認していました。DOM代替処理、マリガン処理、開始演出待機も更新しています。
- 共通基盤に、トラッシュの差し引き処理が行末コメントに含まれて実行されない不具合があり、修正しました。

## 取り入れた判断

添付の「Nのゾロアークexデッキの使い方指針」と記事本文テキストを参照し、独自の条件分岐に落とし込みました。参考URL：https://note.com/yoshi1026/n/n1452ead29be4

- 先攻を選ぶ。初手はゼクロムを優先し、条件が合えばゾロアからシャリタツへ。
- ゾロア2～3体を目指す。ゼクロムとモモワロウの枠を予約し、役割の薄いポケモンでベンチを埋めない。
- 進化、とりひき、サーチ、手張り、ポイントアップ、アンズで攻撃可能な盤面を作る。
- とりひき・ハイパーボールのコストで、最後の重要札や悪エネルギーをなるべく守る。ポイントアップ用の悪エネルギーを落とす判断も含む。
- 相手の公開盤面からドラパルト系を推定。ドロンチ、エネルギー付きドラメシヤ、ヨノワール系統を評価する。
- 借りるポケモンとワザを比較し、ひきさくで足りる場合はランページを温存する。
- 毒＋くさりもち、からておう、アドレナブレイン、パワーレイジを使い分ける。
- Nの城でにげる→悪ポケモンを経由→しはいのくさり、または別の準備済みゾロアークへの交代でランページを再使用する。
- ボスで最後のサイドを取れる場合は、不要なドローより先に勝つ手順を実行する。
- 攻撃できない場合のイベルタルの縛り、終盤のレッドカード、山札切れ回避を評価する。

## 自動対戦と調整

Node.jsを使い、このフォルダで実行してください。追加のnpmパッケージは不要です。

```bash
node sim/run.js test
node sim/run.js verify-info
node sim/run.js eval 100 20000
node sim/run.js optimize --only zoroark --rounds 1 --gens 4 --pop 6 --games 20 --seed 1
```

最後のコマンドは `ai/params/params_zoroark.js` を書き換えます。初期版の配布パラメータは未学習の初期値です。
今回、最適化処理の起動から保存までの動作確認はしましたが、大量対戦によるパラメータ調整は実施していません。
調整対象はゾロア展開目標数、ベンチ展開の閾値、ドローを止める山札枚数です。調整に使っていないseedでも評価してください。

## 現時点の限界と次の強化

- 同梱の60枚リストを対象にしています。Nのヒヒダルマや変化の書など、別構築のコンボは未対応です。
- 判断は人が与えた行動指針と盤面評価を組み合わせたものです。複数ターンの完全な探索、相手の全ての応手の評価は行いません。
- 手札干渉や縛りの価値、次の番の必要札、余分なサーチの使い切りには近似と改善余地があります。
- 特殊なダメージ軽減・無効化・スタジアム・どうぐの全組み合わせを精密に評価する汎用ソルバーではありません。行動の実行自体はエンジンのルール処理に従います。
- 価値関数が未学習なので、ゾロアーク側の共通2段階先読みは無効です。今後は専用の特徴量・価値関数・候補行動の実装と検証が必要です。
- 最初に「選ぶべき手が分かっている盤面」を増やし、安定して正しく解けることを確認します。その後、対戦ログから停滞した理由を集め、重み調整と価値関数学習を進めるのが次の段階です。

## v2：実戦ログを受けた修正

- 通常のきぜつが見えていても、先に次のアタッカーの育成・展開を行います。今の攻撃で勝てる場合は勝利を優先します。
- 進化でとりひきの使用回数を増やし、とりひきを使ってから手張り・どうぐ・サポートを判断します。捨てるカードが高評価というだけで使わない制限を外しました。山札残り3枚以下ではドローを控えます。
- ベンチの予約で、欠けているゼクロムや復帰用ゾロア自身まで出せなくなる不具合を修正しました。
- サーチは手札に確保済みのカードと、実際にベンチへ出せるかを考慮します。
- 進化できないゾロアへの2枚目の手張りより、攻撃を始められるイベルタルへの手張りを優先するようにしました。
- 同じseedの各100試合では、v1の59勝・83勝から、v2は61勝・90勝でした。100試合の差なので強さの有意な向上を証明する比較ではありません。
- 提示された対戦ログには各時点の全手札・山札がないため、同一試合の完全再現はしていません。指摘された問題を個別の盤面にして検証しました。

## v4：2試合の記録を受けた育成・復帰・コスト判断の修正

- きぜつ後の出し先は、次の番の手張り、ポイントアップ（ベンチ限定）、アンズ、モモワロウの場・手札・回収候補、城とにげるコストを使って比較します。ベンチで加速が必要なゾロアークを前に置くことを避けます。一方、そのまま攻撃できてベンチ準備の利点がない場合はアタッカーを前に出します。
- くさりもちは、エネルギーが揃うゾロアークを優先します。しはいのくさりで前に出したときのどくと合わせて攻撃を成立させます。
- 夜のタンカはポケモン・基本エネルギーだけを対象として評価します。サポートの高い評価につられて使用を試みる不具合を修正。必要なモモワロウ・ゼクロム、進化先、手張り用エネルギーなど、その場で使える回収先がある場合に使用します。回収選択にも同じ評価を使います。
- ボスは残りの既知のコピー、手札の重複、残りサイドで保持価値を上げます。直ちに加速に必要なポイントアップと、必要な回収先があるタンカも捨てにくくしました。
- サーチの価値は初期デッキだけでなく、手札・場・進化前・トラッシュを引いた残存候補から計算します。対象を使い切ったサーチ札はとりひきのコスト候補にします。全山札を見た検索で対象がいなかった情報も保持し、同じ空振りを繰り返さないようにしました。サイドの中身は推測にとどまるため、未確認の対象を確認しに行く空振りまでゼロにはできません。

## v5：アドレナブレインを起動する手張りと攻撃の連携

手張り先の固定評価では、悪エネルギーのないマシマシラより育成中のゾロアークを優先することがありました。アドレナブレインが既に使える場合だけでなく、その手張りで使えるようになり、移動後の攻撃と合わせてきぜつさせられる場合を評価するようにしました。

ダメカンの移動元を回復した盤面と、移動先にダメカンをのせた盤面を一時的なAI内の複製で評価します。パワーレイジの打点低下も含めて比較し、特性の移動元・移動先にも計画を引き継ぎます。攻撃役のエネルギーが不足している場合やダメカンがない場合まで、一律にマシマシラを優先するものではありません。攻撃役が既に育っていてダメカンがある場合は、マシマシラへの準備手張りも優先しやすくしています。

3試合目の先攻4ターン目、元の手札・山札・盤面の手張り直前を復元した分岐では、マシマシラへの悪エネルギー、アドレナブレイン、からておうの稽古、ランページサンダー290の順でドラパルトを倒しました。

このログにはジャミングタワーが出ているため、正しいルールではくさりもちの+40は無効です。したがってこの場面の成立手順は、アドレナブレイン30＋からておうを加えたランページサンダー290＝320です。タワーがない盤面なら、アドレナブレイン30＋くさりもちランページ290＝320が成立します。

エンジンのくさりもち加算処理がタワー無効化を通っていなかった不具合も修正しました（index.htmlのダメージ加算条件のみ）。根拠：[公式ジャミングタワー](https://www.pokemon-card.com/card-search/details.php/card/49982/regu/all)、[公式くさりもち](https://www.pokemon-card.com/card-search/details.php/card/45932/regu/all)。

追加の検証は、手張りで320を成立させる盤面、移動先の比較、攻撃役のエネルギーを優先すべき盤面、ダメカンがない盤面、タワー中の打点評価、および実エンジンでの通常時・タワー中の連続手順です。盤面テスト34件、実エンジン手順6件に加え、既存の記録・構成テストも通過しています。

## v6：ジャミングタワーを貼り替えて成立させる攻撃

手札から合法的に出せる別のスタジアムについて、ジャミングタワーを取り除いた後の盤面を評価します。くさりもちの復活、Nの城による無料にげる、しはいのくさりでどくにして攻撃役へ戻す手順、アドレナブレインと手張りを組み合わせたきぜつを比較します。貼り替えによって相手のヒーローマント等も復活するため、そのHP増加も含めます。

- くさりもちが復活して290で倒せる場合は、不要なからておうや攻撃より先にスタジアムを使えます。
- マシマシラへの手張りが必要な場合も、貼り替え後の30＋290を評価します。
- Nの城以外の合法的なスタジアムも、タワーを取り除く候補にします。
- その番にスタジアムを使用済みなら候補にしません。Nの城のにげる計画も、その番ににげるを使用済みなら仮定しません。この情報は公開済みの行動履歴としてAIに渡します。
- きぜつ成立に必要なスタジアムは、とりひきのコストで捨てにくくします。

盤面テスト40件、実エンジン手順7件、記録・構成検査を通過しました。実エンジンではタワー→Nの城→無料にげる→しはいのくさり→どくのくさりもちランページ290でのきぜつを検証しました。依然として手札にある資源を中心とした近似評価で、すべてのスタジアム固有効果や複数ターン先の応手を網羅する探索ではありません。
