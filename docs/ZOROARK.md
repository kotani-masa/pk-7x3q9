# Nのゾロアークex CPU AI 初期版

2026-10-27。エミュレータ本体は今回添付の最新版 `index (2)(1).html` を基準にしています。AI接続用の差分と、整理後のAIファイルへの読み込み先を追加しました。画面・モーションなどの処理は今回の添付版を保持しています。AI・自動対戦ツールはGitHub main `52e8bc1d346cba02d0187c8b8d270ebdaed4f941` からの追加・修正です。
GitHubの公開内容にはまだ反映していません。

## 使い方

ZIPを展開し、フォルダ内の `index.html` を開いてください。既存のCPU戦メニューから、CPU側に「Nのゾロアークex」デッキを選ぶと専用AIが自動選択されます。
`ai` フォルダを `index.html` と同じ場所に残してください。カード画像の取得にはインターネット接続が必要です。
既存フォルダへ上書きする場合はバックアップしてから行ってください。このZIPの本体は今回添付された最新版に差し替え済みです。

## 調べて分かったこと

- 自動対戦の基盤は既存の `sim/lib/headless.js` にあります。ブラウザ画面を操作せず、本体と同じルール処理をNode.jsで実行します。
- `sim/training/optimize.js` は勝率を使って行動の重みを調整するクロスエントロピー法です。ゼロから新しい戦略を発見する強化学習とは異なります。
- 既存の専用AIと学習済み価値関数はドラパルトとメガレックウザ用です。これらの価値関数をそのままゾロアークに使うことはできません。
- 既存の共通ダメージ推定では、ナイトジョーカーの借りるワザ、毒＋くさりもち、パワーレイジの判断が不足していました。今回の専用AIはここを自分で評価します。
- 現在のHTMLに対し、既存のヘッドレス起動は最後のインラインscriptを本体と誤認していました。DOM代替処理、マリガン処理、開始演出待機も更新しています。
- 共通基盤に、トラッシュの差し引き処理が行末コメントに含まれて実行されない不具合があり、修正しました。

## 取り入れた判断

添付の「Nのゾロアークexデッキの使い方指針」と記事本文テキストを参照し、独自の条件分岐に落とし込みました。参考URL：https://note.com/yoshi1026/n/n1452ead29be4
記事本文は配布物に含めていません。

- 先攻を選ぶ。初手はゼクロムを優先し、条件が合えばゾロアからシャリタツへ。
- ゾロア2～3体を目指す。ゼクロムとモモワロウの枠を予約し、役割の薄いポケモンでベンチを埋めない。
- 進化、とりひき、サーチ、手張り、ポイントアップ、アンズで攻撃可能な盤面を作る。
- とりひき・ハイパーボールのコストで、最後の重要札や悪エネルギーをなるべく守る。ポイントアップ用の悪エネルギーを落とす判断も含む。
- 相手の公開盤面からドラパルト系を推定。ドロンチ、エネルギー付きドラメシヤ、ヨノワール系統を評価する。
- 借りるポケモンとワザを比較し、ひきさくで足りる場合はランページを温存する。
- 毒＋くさりもち、からておう、アドレナブレイン、パワーレイジを使い分ける。
- Nの城でにげる→悪ポケモンを経由→しはいのくさり、または別の準備済みゾロアークへの交代でランページを再使用する。
- ボスで最後のサイドを取れる場合は、不要なドローより先に勝つ手順を実行する。
- 攻撃できない場合のイベルタルの縛り、終盤のレッドカード、山札切れ回避を評価する。

## 検証

今回添付の最新版へ差し替え、フォルダ整理後にも、本体と同じルール処理を使って再検証した、先読みなしの対戦。乱数seedは20000～20099、ゾロアーク側の座席を交互に変更。各100試合、上限80ターン。
相手は同梱の既存AIと既存デッキです。ボム型専用の勝率ではありません。

| 相手 | 勝ち | 負け | 引き分け・上限到達 | 実行エラー・未完了 |
|---|---:|---:|---:|---:|
| ドラパルト | 59 | 41 | 0 | 0 |
| メガレックウザ | 83 | 17 | 0 | 0 |

100試合なので誤差があります。既存AIに対するこの条件での結果であり、人間相手の勝率や「最強」を証明する数字ではありません。
対戦集計の元データは `sim/results/zoroark.json`。

個別の判断テスト11件と実エンジンテスト3件も通過しています。後者は、マリガン後の開始と先攻ドロー、アドレナブレイン30＋毒くさりもちランページ290でドラパルトを倒す手順、およびNの城＋モモワロウでランページを再使用する手順を確認します。
情報制限テストではゾロアークを含む対戦を確認しています。AIは盤面本体とは別の実行環境に置かれ、JSONで渡された情報のみを使用します。
ブラウザ上の画面操作を含む通し検証は未実施です。

## 自動対戦と調整

Node.jsを使い、このフォルダで実行してください。追加のnpmパッケージは不要です。

```bash
node sim/run.js test
node sim/run.js verify-info
node sim/run.js eval 100 20000
node sim/run.js optimize --only zoroark --rounds 1 --gens 4 --pop 6 --games 20 --seed 1
```

最後のコマンドは `ai/params/params_zoroark.js` を書き換えます。初期版の配布パラメータは未学習の初期値です。
今回、最適化処理の起動から保存までの動作確認はしましたが、大量対戦によるパラメータ調整は実施していません。
調整対象はゾロア展開目標数、とりひきのコスト許容値、ベンチ展開の閾値、ドローを止める山札枚数です。調整に使っていないseedでも評価してください。

## 現時点の限界と次の強化

- 同梱の60枚リストを対象にしています。Nのヒヒダルマや変化の書など、別構築のコンボは未対応です。
- 判断は人が与えた行動指針と盤面評価を組み合わせたものです。複数ターンの完全な探索、相手の全ての応手の評価は行いません。
- 手札干渉や縛りの価値、次の番の必要札、余分なサーチの使い切りには近似と改善余地があります。
- 特殊なダメージ軽減・無効化・スタジアム・どうぐの全組み合わせを精密に評価する汎用ソルバーではありません。行動の実行自体はエンジンのルール処理に従います。
- 価値関数が未学習なので、ゾロアーク側の共通2段階先読みは無効です。今後は専用の特徴量・価値関数・候補行動の実装と検証が必要です。
- 最初に「選ぶべき手が分かっている盤面」を増やし、安定して正しく解けることを確認します。その後、対戦ログから停滞した理由を集め、重み調整と価値関数学習を進めるのが次の段階です。
